# Phase 3 — UI Design Contract

> Visual and interaction contract for the Streamlit dashboard (`src/f1_prediction/dashboard.py`). Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Note on scope:** This phase's stack is Python/Streamlit + Plotly, not React/Next.js/Vite (locked in `PROJECT.md` §Key Decisions — "XGBoost + Streamlit over LightGBM + Dash"). The shadcn initialization gate in the researcher's instructions applies only to React/Next.js/Vite projects and is **not applicable** here. ## Design System

| Property | Value |
|----------|-------|
| Tool | none (shadcn gate not applicable — Python/Streamlit stack, confirmed via 03-RESEARCH.md and codebase scan) |
| Preset | not applicable |
| Component library | Streamlit native widgets (`st.tabs`, `st.dataframe`, `st.container`, `st.metric`, `st.caption`) + Plotly (`go.Bar`, horizontal orientation) for the win-probability chart |
| Icon library | none — do not use emoji as icons/status indicators (project convention: emojis only when explicitly requested). Use plain-text badges (e.g. `"LIVE"`) with color/weight for emphasis instead. |
| Font | Streamlit default theme font — system sans-serif via `theme.base = "dark"` in `.streamlit/config.toml`. No custom font import; keeps the dependency surface minimal (default). |

**Theme base (default, not yet locked by CONTEXT.md — Claude's discretion, documented here as the contract):** Dark theme (`.streamlit/config.toml`, `[theme] base = "dark"`). Rationale: matches a live-broadcast/telemetry aesthetic appropriate for a race dashboard, and gives strong contrast for team-colored bars. This is a default, not a locked user decision — flag to the user if a light theme is preferred instead.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Inline gaps in custom badge/caption HTML (LIVE badge padding, table cell inner padding) |
| sm | 8px | Compact spacing inside the side data table; `st.columns(gap="small")` |
| md | 16px | Default spacing between chart and side table; `st.columns(gap="medium")` (Streamlit default) |
| lg | 24px | Section padding inside `st.container(border=True)` wrapping the chart+table block |
| xl | 32px | Gap between the page title and the tab row |
| 2xl | 48px | Not used in this phase (single-page dashboard, no major section breaks) |
| 3xl | 64px | Not used in this phase |

Exceptions: Streamlit does not expose raw pixel control for native layout (`st.columns`, `st.container`) — only keyword gaps (`"small"`/`"medium"`/`"large"`). The px values above are the target contract for any **custom HTML/CSS** this phase adds (the `LIVE` badge, the freshness caption) so they stay visually consistent with the 8-point scale; native Streamlit layout should use `gap="small"` for xs/sm and `gap="medium"` (default) for md, with `st.divider()` / `st.container(border=True)` padding standing in for lg/xl.

## Typography

Streamlit's native heading elements (`st.title`, `st.header`, `st.subheader`) keep their own built-in scale untouched — do not override via custom CSS. The declared sizes below apply to **custom markdown/HTML elements this phase adds**: the page title, tab-section subheaders (rendered via `st.subheader`, mapped to the nearest role), the `LIVE` badge, and the freshness caption.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 | 1.5 |
| Label | 14px | 400 | 1.5 |
| Heading | 20px | 600 | 1.2 |
| Display | 28px | 600 | 1.2 |

Only two weights used across the app: 400 (regular, body/labels) and 600 (semibold, headings/display/badge text). No third weight anywhere.

- **Display (28/600/1.2):** Page title — `st.title("F1 Win Probability — {race name}")`.
- **Heading (20/600/1.2):** Tab section subheaders (e.g. "Pre-Race Win Probability", "In-Race Win Probability"); `LIVE` badge text.
- **Body (16/400/1.5):** Plotly chart hover labels, `st.dataframe` cell text, driver full names.
- **Label (14/400/1.5):** `st.caption` freshness timestamp, driver acronym column, small metadata text (tyre compound, gap values).

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#0E1117` | Page background (Streamlit dark theme default `backgroundColor`) |
| Secondary (30%) | `#262730` | Card/container backgrounds — `st.container(border=True)` wrapping the chart+table block, side data table background (Streamlit dark theme default `secondaryBackgroundColor`) |
| Accent (10%) | `#E10600` (official F1 red) | Reserved for: the `LIVE` status badge background+text, the active-tab underline/selection indicator, and a left-border highlight on the P1/leader row in the side data table. |
| Destructive | not applicable this phase | No destructive actions exist in Phase 3 (dashboard is read-only, per CONTEXT.md D-06/Integration Points). Error states (missing model artifact, no session found) use Streamlit's native `st.error()` red styling — no custom destructive token needed. |

Accent reserved for: `LIVE` badge, active tab indicator, P1/leader row highlight border. **Not used** for the win-probability bar chart itself — those bars are color-coded per constructor/team using OpenF1 `team_colour` values (D-05, data-driven, not part of the UI chrome accent budget).

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | None — dashboard is passive/read-only, no manual refresh button (D-08). Tab labels are the only interactive navigation: **"Pre-Race"** and **"In-Race"** (exact strings, Title Case, no icons/emoji). |
| Empty state — Pre-Race tab (no qualifying data yet) | Heading: "No qualifying data yet" · Body: "Pre-race probabilities appear once qualifying session data is available for this race. Run the backfill or wait for the poller to ingest qualifying results." |
| Empty state — In-Race tab (race not started) | Heading: "Race hasn't started" · Body: "In-race probabilities begin updating once the first lap is recorded. This tab refreshes automatically every 15 seconds — no action needed." |
| Error state — no race session found | "No race session found in the database. Run `scripts/backfill.py` or start the live poller, then relaunch the pipeline." |
| Error state — model artifact missing | "Prediction model not found. Run `python scripts/train.py --model prerace` (and `--model inrace`) to generate `data/models/*.joblib`, then restart `python -m src.f1_prediction.pipeline`." |
| Destructive confirmation | None — dashboard performs no destructive actions in this phase (read-only against SQLite). |
| Freshness indicator (in-race tab, always visible) | `"LIVE · Lap {lap_number} · updated {HH:MM:SS}"` — rendered as a caption near the chart title so the user can visually confirm probabilities aren't stale (addresses 03-RESEARCH.md's flagged correctness-as-safety concern). |
| Freshness indicator (pre-race tab, always visible) | `"Pre-race · computed {HH:MM:SS}"` — no `LIVE` badge on this tab (static, renders once per page load). |
| Live status badge | Plain-text badge, not emoji: `"LIVE"` on accent-red background (`#E10600`), white/semibold text, shown only on the In-Race tab while `prediction_type='inrace'` rows exist for the current session. Not shown on the Pre-Race tab. |
