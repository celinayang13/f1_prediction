| poll_once → inference hook → predictions | New external lap data drives model inference and DB writes |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-05 | Information Disclosure | Stale probabilities shown as live | medium | mitigate | Freshness line "LIVE · Lap N · updated HH:MM:SS" surfaces lap_number + computed_at so the user can confirm currency (correctness-as-safety per RESEARCH); fresh connection per fragment rerun avoids stale WAL snapshot (Pattern 4). |
| T-03-06 | Denial of Service | Fragment 15s reads hammering SQLite | low | accept | 15s cadence against a single-writer WAL DB with ~20-row result sets is well within SQLite capacity; read-only, no lock contention. Accepted. |
| T-03-07 | Tampering | inference hook writing bad rows | low | mitigate | Per-(session,lap) DELETE-before-insert keeps re-runs idempotent; softmax reuse guarantees sum-to-1; `text()` + bound params only. |
| T-03-08 | Denial of Service | inference exception crashing scheduler thread | medium | mitigate | Reuse poller's EVENT_JOB_ERROR listener + job-level try/except so an inference failure logs and the scheduler survives (matches poller.py convention). |
</threat_model>
