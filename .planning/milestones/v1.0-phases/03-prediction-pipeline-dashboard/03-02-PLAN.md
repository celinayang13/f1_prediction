<objective>
Deliver the first end-to-end user-visible slice: a user runs `python -m src.f1_prediction.pipeline`, it auto-detects the latest race, computes pre-race win probabilities from qualifying/practice features, and writes them to the `predictions` table; the user then runs `streamlit run src/f1_prediction/dashboard.py` and sees a ranked, team-colored horizontal bar chart of pre-race win probabilities at localhost:8501.

Purpose: This slice makes the pipeline→SQLite→dashboard chain real for the pre-race case (DASH-02, DASH-04), establishing every shared contract the in-race slice (Plan 03) then extends. After this plan a real user can do something they could not before: open the dashboard and see pre-race predictions.
Output: `inference/prerace.py`, `pipeline.py` (startup path), and `dashboard.py` + `dashboard_lib/` with a working Pre-Race tab.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| OpenF1 `/v1/drivers` → pipeline → raw_drivers | Untrusted external JSON persisted to SQLite |
| SQLite predictions table → dashboard process | The only channel between writer (pipeline) and reader (dashboard) |
| Browser → Streamlit (localhost:8501) | Local-only, no auth by design (DASH-04) |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-01 | Tampering | `sync_drivers_for_session` raw_drivers insert | medium | mitigate | Whitelist `_DRIVER_FIELDS` extraction before insert; `text()` + bound `:param` only — never insert the raw API dict (V5 input validation, same pattern as poller.py). |
| T-03-02 | Information Disclosure | Streamlit network bind | high | mitigate | Do not pass `--server.address 0.0.0.0`; default localhost bind keeps the no-auth dashboard (DASH-04) unreachable off-host. Enforced by grep gate (no `0.0.0.0` in dashboard.py). |
| T-03-03 | Tampering | dashboard writing to DB | medium | mitigate | Dashboard is read-only (D-06); acceptance criterion asserts no INSERT/UPDATE/DELETE in dashboard code. |
| T-03-04 | Denial of Service | OpenF1 rate limits (drivers fetch) | low | mitigate | `sync_drivers_for_session` fetches once per session_key (check-then-skip), inheriting `_fetch()` tenacity backoff. |
</threat_model>
