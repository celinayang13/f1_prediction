## Phase Goal

**As a** developer building the F1 prediction system, **I want to** run one backfill command that ingests every race + qualifying + relevant practice session across 2022–2025 (with weather flags and tyre stint data), **so that** Phase 2's feature builder has the raw substrate it needs to compute pre-race and in-race features without re-fetching upstream data.

<objective>
Widen the Walking Skeleton from Plan 01 into a complete historical backfill:
1. Extend the ORM schema to all 5 raw tables (`raw_laps` widens to full OpenF1 column set; `raw_stints`, `raw_pit_stops`, `raw_positions` added; `raw_weather` added for DATA-02) — per D-09, D-10.
2. Add the OpenF1 client (`openf1_client.py`) using `httpx.AsyncClient` + `tenacity` exponential backoff (D-12, RESEARCH Pattern 4) and the OpenF1 loader (`openf1_loader.py`) that orchestrates one session.
3. Extend the FastF1 loader (`fastf1_loader.py`) to ingest stints, pit stops, positions, and weather (not just laps as in Plan 01).
4. Widen `scripts/backfill.py` from one-shot to year-loop, routing year ≤ 2022 → FastF1 and year ≥ 2023 → OpenF1 (Pitfall 4). Preserve resumability (D-11).
5. Add weather wet/dry/mixed classification from the `rainfall` flag (RESEARCH Don't Hand-Roll table).
6. Cover DATA-01 (historical fetch for 2022–2025), DATA-02 (weather), DATA-04 (tyre stints).

Purpose: Complete the raw-data substrate. After this plan a developer has every lap, stint, pit, position, and weather flag for 2022–2025 race weekends in SQLite, ready for feature engineering in Plan 03.

Output: All 5 raw tables + `raw_weather` populated; backfill is resumable and idempotent; tests use recorded JSON fixtures so the OpenF1 path is exercised without network.
</objective>
