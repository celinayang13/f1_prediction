## Phase Goal

**As a** developer who has backfilled 2022–2025 raw F1 data, **I want to** transform that data into two flat feature tables and start a live poller that streams race-day laps into the same tables, **so that** Phase 2's model trainer can read `features_prerace` / `features_inrace` directly and Phase 3's inference loop can wake up on each new lap.

<objective>
Complete Phase 1 by adding the two feature tables and the live poller:
1. ORM models `FeaturesPrerace` and `FeaturesInrace` matching D-01/D-02/D-03 exactly.
2. Feature builder under `src/f1_prediction/features/` that reads raw tables and writes the feature tables. Pure functions per feature (so Phase 2 can re-use them or audit them).
3. Cross-session aggregates pre-computed and stored in `features_prerace` per D-04: `circuit_win_rate`, `circuit_avg_finish`, `constructor_pace_delta` — Phase 2 reads them without joins.
4. `scripts/build_features.py` standalone CLI (D-13).
5. `scripts/backfill.py` triggers `build_all_features` at end unless `--skip-features` (D-13).
6. Live poller (`src/f1_prediction/live/poller.py`) using `APScheduler.BackgroundScheduler` (RESEARCH Pattern 5) — polls OpenF1 `/v1/laps`, `/v1/intervals`, `/v1/position`, `/v1/stints` every 30 seconds for an active session, dedupes against existing rows by `(session_key, driver_number, lap_number)`, inserts into the same raw tables. Pitfall 7 mitigation: `session_window.is_session_active` checks if `/v1/sessions.date_start − 30min ≤ now ≤ date_end + 30min`; the poller no-ops outside the window.
7. `scripts/live_poller.py` CLI: takes `--session-key INT`, starts the scheduler, blocks until SIGINT.
8. Cover DATA-03 (live polling).

Purpose: Phase 1 ends when Phase 2 can `SELECT * FROM features_prerace WHERE year = 2024` and get a ready-to-train DataFrame, and a developer can start the live poller against an active race weekend session and watch new laps stream into `raw_laps`.

Output: Both feature tables populated; live poller starts, polls, dedupes, and stops cleanly.
</objective>
